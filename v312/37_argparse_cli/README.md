# Project 37: A Command-Line File Organizer with argparse

A small command-line tool built with the standard `argparse` module. It takes a source folder and a target folder from the command line and moves each file in the source folder into a category subfolder (`Documents`, `Images`, `Code` or `Others`) under the target folder, based on its extension. A `--dry-run` flag shows what would happen without moving anything.

| Topic | Key API |
|-------|---------|
| Program description and example line in the help screen | `ArgumentParser(description=..., epilog=...)` |
| Required positional arguments (`source`, `target`) | `add_argument("source")` |
| On/off flag with a short and a long name | `add_argument("-d", "--dry-run", action="store_true")` |
| Automatic `--help` and usage errors | `parse_args()` |

## How It Works
- `parse_args()` reads `source`, `target` and the optional `-d` / `--dry-run` flag. If a positional argument is missing, argparse prints a usage line and exits with code `2`.
- `organize_files()` loops over the files directly inside the source folder (subfolders are skipped) and looks up the lowercase extension in a fixed table:
  - `.txt`, `.pdf`, `.docx` → `Documents`
  - `.jpg`, `.jpeg`, `.png` → `Images`
  - `.py`, `.sh`, `.js` → `Code`
  - anything else → `Others`
- Without `--dry-run`, the category folder is created if needed and the file is moved with `shutil.move()`. With `--dry-run`, only the planned moves are printed and nothing is created or moved.

A few things to keep in mind:
- If the source folder does not exist, the script prints an error but still exits with code `0`.
- If a file with the same name already exists in the target category folder, it is overwritten without a warning.
- Files are listed in the order the file system returns them, which is not necessarily alphabetical.

## Running

Show the help screen generated by argparse:
```bash
python3 main.py --help
```
```text
usage: main.py [-h] [-d] source target

A robust CLI tool to organize directory files smoothly by category extensions.

positional arguments:
  source         Path to the unsorted source directory containing target
                 items.
  target         Path to the destination directory where categorized results
                 will be saved.

options:
  -h, --help     show this help message and exit
  -d, --dry-run  Simulates execution flow by printing layout actions without
                 moving any files.

Example: python3 main.py ./downloads ./sorted_archive --dry-run
```
Python versions before 3.10 print `optional arguments:` instead of `options:`.

Create a test folder with a few empty files and do a dry run first:
```bash
mkdir test_source && touch test_source/doc1.pdf test_source/photo2.png test_source/script3.py
python3 main.py ./test_source ./test_target --dry-run
```
```text
--- Initiating File Organization Layout ---
Source Location : /path/to/test_source
Target Location : /path/to/test_target
[Notice] DRY-RUN MODE ACTIVE: No files will actually be modified.

 -> Mapping: photo2.png -> [Images] folder
 -> Mapping: script3.py -> [Code] folder
 -> Mapping: doc1.pdf -> [Documents] folder
--------------------------------------------------
Execution complete. Total items logged/processed: 3
```
`test_target` is not created during a dry run. Run the same command without `--dry-run` to actually move the files:
```bash
python3 main.py ./test_source ./test_target
```
After this, `test_source` is empty and the files are in `test_target/Documents`, `test_target/Images` and `test_target/Code`.

Calling the script without arguments shows the usage error:
```text
usage: main.py [-h] [-d] source target
main.py: error: the following arguments are required: source, target
```

# Project 34: Package Management with Poetry

A small example of managing a project's dependencies with [Poetry](https://python-poetry.org/) instead of `pip` and a `requirements.txt` file. The dependencies are declared in `pyproject.toml`, and the exact versions Poetry resolved (including sub-dependencies and their hashes) are pinned in `poetry.lock`. Anyone who runs `poetry install` on this folder gets the same package versions.

`src/main.py` uses the third-party `rich` package to print a table showing which Python interpreter it runs under. When you start it with `poetry run`, that interpreter is the one in the virtual environment Poetry created for the project.

## How It Works
- `pyproject.toml` declares two runtime dependencies (`rich >=15,<16` and `requests >=2.34.2,<3`) and one development dependency in the `dev` group (`pytest >=9.0.3,<10`). `requests` and `pytest` are not used by the code; they are there to show runtime and development groups. The project has no tests.
- `poetry.lock` pins 14 packages in total (the three above plus their sub-dependencies, e.g. `certifi`, `urllib3`, `markdown-it-py`, `pygments`).
- `poetry install` creates a virtual environment and installs exactly the locked versions. `poetry run <command>` runs a command inside that environment without activating it.
- The text "Successfully Resolved via Poetry" in the output is a fixed string in the code. The table only proves that `rich` could be imported, not how it was installed.

## Requirements
- Python 3.12 or newer (`requires-python = ">=3.12"` in `pyproject.toml`; the locked packages themselves need 3.10+). Tested on 3.12.3.
- Poetry 2.3 or newer. The lock file was generated by Poetry 2.4.1, and the dev group uses the standard `[dependency-groups]` table. Poetry 2.1 and 2.2 reject this lock file with "pyproject.toml changed significantly since poetry.lock was last generated". Tested with Poetry 2.3.0, 2.4.0 and 2.5.1.

Install Poetry with `pipx` (recommended):
```bash
sudo apt install pipx
pipx install poetry
poetry --version
```
or with the official installer:
```bash
curl -sSL https://install.python-poetry.org | python3 -
```

## Running
```bash
cd 34_poetry_package_management
poetry install --no-root
poetry run python3 src/main.py
```
Use `--no-root`. This folder is not an installable package, so a plain `poetry install` installs all dependencies and then stops with an error (exit code 1):
```text
Error: The current project could not be installed: No file/folder found for package 34-poetry-package-management
If you do not want to install the current project use --no-root.
```
Another option is to add `package-mode = false` under a `[tool.poetry]` table in `pyproject.toml`. After that, a plain `poetry install` also works.
